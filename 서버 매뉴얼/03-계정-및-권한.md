# 계정 및 권한

[목차](../README.md)

## 사용자 확인

```bash
whoami
id
printf '%s\n' "$HOME"
groups
sudo -l
```

UID/GID와 홈 경로가 혼재하므로 이전 문서의 UID 4000번대 규칙이나 교육 계정 일괄 생성 스크립트를 현행 정책으로 사용하지 않습니다. 계정 생성·만료·삭제는 관리자에게 요청합니다. 개인별 계정과 프로젝트 그룹 목록은 공개하지 않습니다.

현재 Slurm은 Linux 계정으로 작업을 실행합니다. 회계 DB나 별도 Slurm 계정 등록은 구성돼 있지 않으며 일반 사용자 배치 실행을 확인했습니다.

## 관리자 계정 생성 예시

이름과 UID/GID 정책을 먼저 정합니다. 다음은 정책 확정 후 사용하는 일반 절차이며 자동 실행 스크립트가 아닙니다.

```bash
getent passwd NEWUSER
sudo adduser NEWUSER
id NEWUSER
```

프로젝트 경로는 기존 소유자·그룹과 ACL을 확인한 뒤 지정합니다. `/data` 전체에 재귀적인 `chown`·`chmod`를 실행하지 않습니다.

```bash
ls -ld /data /data/PROJECT
getent group GROUPNAME
sudo usermod -aG GROUPNAME NEWUSER
```

그룹 변경은 새 로그인에서 확인합니다. `docker` 그룹은 호스트에 강한 권한을 주므로 일괄 부여하지 않습니다. sudo 권한은 `sudo -l -U NEWUSER`, 문법은 `sudo visudo -c`로 확인합니다.

## 계정 종료

먼저 작업·프로세스와 데이터 소유권을 확인합니다.

```bash
squeue -u USERNAME
ps -u USERNAME -o pid,etime,cmd
getent passwd USERNAME
```

비밀번호 잠금만으로 공개키 접근까지 차단되는 것은 아닙니다. 접근 중단은 공개키·SSH 정책·기존 세션도 점검합니다. 홈 삭제·대량 계정 삭제는 데이터 보존 확인 후 별도로 수행합니다.
