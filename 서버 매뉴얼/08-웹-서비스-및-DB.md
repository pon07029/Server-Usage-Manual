# 웹 서비스 및 DB

[목차](../README.md) · 2026-10-24 확인 상태. 포트 수신·서비스 실행은 확인했지만 브라우저 로그인이나 외부 경로 전체를 검증한 것은 아닙니다.

## Nginx 및 TLS

Nginx 1.18.0이 HTTP 80 / HTTPS 443을 사용합니다. 활성 사이트는 `/etc/nginx/sites-enabled/lab-website`이며 실제 파일은 `/etc/nginx/sites-available/lab-website`입니다. TLS 인증서 경로는 `/etc/nginx/ssl/site.crt`입니다.

Certbot 실행 파일과 갱신 설정은 이번 점검에서 확인되지 않았습니다. 기존 Let's Encrypt 자동 발급·갱신 예제를 현행 운영 절차로 사용하지 않습니다. 인증서 갱신 주체와 만료일을 관리자가 확인합니다.

```bash
sudo nginx -t
systemctl status nginx --no-pager
sudo journalctl -u nginx -n 50 --no-pager
sudo openssl x509 -in /etc/nginx/ssl/site.crt -noout -dates
```

운영 변경은 파일 백업·문법 검사 후 적용합니다. Apache2는 현재 서비스가 failed 상태로 확인됐으며 운영 웹 서버로 안내하지 않습니다.

## RStudio Server

| 항목 | 확인값 |
|---|---|
| 버전 | 2023.12.1+402 |
| 서비스 / 포트 | `rstudio-server` / 8787 |
| 설정 | `/etc/rstudio/rserver.conf` |
| R 경로 | `rsession-which-r=/usr/bin/R`, R 4.4.2 |

서버 계정과 웹 로그인 허용 정책은 관리자에게 확인합니다. SSH 키 등록만으로 RStudio 비밀번호 로그인이 설정되는 것은 아닙니다. 현재 설정에 `auth-minimum-user-id=0`이 있으나 사용자 분석은 개인 계정으로 수행합니다.

PC에서 SSH 터널을 사용할 수 있습니다. 터미널을 유지한 채 브라우저에서 `http://localhost:18787`을 엽니다.

```bash
ssh -N -L 18787:127.0.0.1:8787 -p 22 USERNAME@SERVER
```

```bash
systemctl status rstudio-server --no-pager
sudo journalctl -u rstudio-server -n 50 --no-pager
```

대용량 분석은 RStudio 세션에서 장기간 직접 돌리기보다 스크립트로 작성해 Slurm에 제출합니다.

## Shiny Server

| 항목 | 확인값 |

| 버전 | 1.5.20.1002 |
| 서비스 / 포트 | `shiny-server` / 3838 |
| 설정 | `/etc/shiny-server/shiny-server.conf` |
| 앱 디렉터리 | `/srv/shiny-server` |
| 로그 디렉터리 | `/var/log/shiny-server` |

실제 앱 배포 권한과 주소는 관리자에게 받습니다. 공용 앱 폴더나 패키지를 임의로 덮어쓰지 않습니다.

```bash
systemctl status shiny-server --no-pager
sudo journalctl -u shiny-server -n 50 --no-pager
```

## PHP

CLI는 PHP 8.3.3, 실행 중인 서비스는 `php8.2-fpm` 8.2.15입니다. CLI 버전만 보고 웹 서비스 버전으로 판단하지 않습니다.

```bash
php --version
/usr/sbin/php-fpm8.2 -v
systemctl status php8.2-fpm --no-pager
```

## MySQL

MySQL 8.0.46이 `mysql` 서비스로 실행됩니다. `/etc/mysql/mysql.conf.d/mysqld.cnf`의 `bind-address`는 `127.0.0.1`입니다. 원격 3306 직접 접속을 전제로 안내하지 않습니다.

```bash
mysql --version
systemctl status mysql --no-pager
sudo journalctl -u mysql -n 50 --no-pager
mysql -u DBUSER -p
```

DB 계정·권한은 관리자가 발급합니다. PC 클라이언트가 필요하면 SSH 터널을 사용합니다.

```bash
# PC에서 실행 후 DB 클라이언트의 접속 대상: 127.0.0.1:13306
ssh -N -L 13306:127.0.0.1:3306 -p 22 USERNAME@SERVER
```

DB 사용자·스키마·비밀번호는 이번 확인 범위에 포함하지 않았습니다. DB 백업은 실행 중인 데이터 디렉터리 단순 복사가 아니라 일관성을 보장하는 별도 절차가 필요합니다.
