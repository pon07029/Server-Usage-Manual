# 변경 및 검증 기록

[목차](../README.md) · 기준일: 2026-10-24 (Asia/Seoul)

## 조사 범위

관리자 SSH로 OS·CPU·메모리·마운트·GPU, 패키지/실행 파일 버전, systemd 서비스, 수신 포트, SSH 유효 설정, Slurm 설정과 상태, Docker 저장소·런타임, 웹서비스 설정의 필요한 항목을 읽었습니다. 사용자별 Conda 실행 파일 존재도 확인했습니다.

개인 연구 데이터 내용, 비밀번호·개인키, DB 테이블, 웹 앱 로그인과 GUI 세션, 외부 클라이언트 연결 전체, 개별 Conda 패키지 및 모든 분석 도구의 기능은 조사하지 않았습니다.

## 검증 결과와 재확인 명령

서버 설정 시 root CPU 작업, 일반 사용자 CPU 작업, GPU 예약 후 `nvidia-smi` 작업이 모두 종료 코드 0으로 완료됐습니다. GPU 테스트는 장치 접근·가시성 확인이며 학습·CUDA 연산 성능 검증은 아닙니다.

문서의 실행 예제도 일반 사용자 권한으로 별도 제출해 모두 성공했습니다. CPU 예제 작업 4에서 `CPU_EXAMPLE_OK`, GPU 예제 작업 5에서 `CUDA_VISIBLE_DEVICES=0` 및 `GPU_EXAMPLE_OK`, 배열 작업 6의 인덱스 1·2·3에서 각각 `ARRAY_EXAMPLE_OK`를 확인했습니다. `sbatch --wait`가 모두 0으로 종료했고 이후 대기열은 비어 있습니다.

12개 Markdown 파일의 로컬 링크·코드 블록, PowerShell 코드의 구문, 세 배치 파일의 `bash -n`, Git 공백 검사를 확인했습니다. Windows에서도 배치 파일 줄바꿈을 유지하도록 `.gitattributes`에 LF를 지정했습니다.

```bash
sbatch --version
scontrol ping
sinfo -N -l
scontrol show node vbmi
systemctl is-active munge slurmctld slurmd
systemctl is-enabled munge slurmctld slurmd
sbatch --wait examples/cpu.sbatch
sbatch --wait examples/gpu.sbatch
sbatch --wait examples/array.sbatch
squeue
```

다음 개정에서도 날짜와 조사 범위를 갱신합니다. 서비스가 실행 중이라는 확인과 사용자 관점의 전체 기능 검증을 구분합니다.
