# 운영 점검 및 백업

[목차](../README.md)

## 자원 확인

`htop`, `btop`(Snap), `tmux`, `screen`, `rsync`가 있습니다. Glances나 중앙 대시보드 설치를 전제로 하지 않습니다.

```bash
htop
free -h
df -h / /data
nvidia-smi
squeue
ps -eo pid,user,comm,%cpu,%mem --sort=-%cpu | head -20
```

전체 RAM·GPU 사용량과 Slurm 예약량은 다릅니다. 현재 Slurm 밖의 분석이 실행 중이므로 `squeue`만으로 서버 부하를 판단하지 않습니다. 모니터링 종료는 보통 Ctrl+C, htop 종료는 F10입니다.

## 서비스 및 로그

journald와 rsyslog가 실행 중입니다.

```bash
systemctl --failed
sudo journalctl -p err -b -n 100 --no-pager
sudo journalctl -u ssh -u slurmctld -u slurmd -n 80 --no-pager
sudo journalctl -k --since today | grep -Ei 'out of memory|oom|killed process|I/O error'
sudo tail -n 50 /var/log/auth.log
sudo tail -n 50 /var/log/nginx/error.log
```

Docker 로그는 대상 컨테이너에 대해 `docker logs --tail=100 CONTAINER`로 확인합니다. 서비스별 journal은 [웹 서비스](08-웹-서비스-및-DB.md)를 참고합니다. 로그에는 사용자·주소·토큰이 포함될 수 있어 공개 저장소에 원문을 올리지 않습니다.

## 패키지 및 업데이트

현재 상태 조회:

```bash
apt list --upgradable
apt-cache policy slurm-client slurmctld slurmd
dpkg-query -W nginx mysql-server rstudio-server shiny-server xrdp
```

관리자가 패키지를 설치할 때는 유지보수 범위를 정하고 다음 순서로 진행합니다.

```bash
sudo apt-get update
sudo apt-get install PACKAGE
```

전체 업그레이드·재부팅·서비스 재시작은 실행 중인 분석과 사용자 세션에 영향을 줍니다. 오래된 저장소 추가 예제나 광범위한 자동 업그레이드를 기본 사용법으로 제공하지 않습니다.

## 접근 보호 및 방화벽

UFW가 활성화돼 있고 Fail2Ban의 `sshd` jail이 실행 중입니다. Fail2Ban이 시간대만으로 접속을 차단한다고 가정하지 않습니다.

```bash
sudo ufw status verbose
sudo fail2ban-client status
sudo fail2ban-client status sshd
sudo sshd -t
sudo ss -lntp
```

방화벽 허용 규칙과 실제 서비스 수신 상태는 별개입니다. 현재 접속 세션을 유지한 상태에서 변경 내용을 검토하고, SSH 포트·인증 방식을 문서 예제만 보고 바꾸지 않습니다.

## 백업 확인

`rsync`·`tar`는 있지만 연구 데이터의 자동 백업 대상·보존 기간·복원 검증은 확인되지 않았습니다. root crontab과 시스템 timer 점검에서 연구 데이터 백업 작업은 확인되지 않았고, 개인 계정·외부 장비의 백업 존재 여부는 조사하지 않았습니다.

`dpkg-db-backup.timer`는 패키지 DB용이며 연구 데이터 백업이 아닙니다. root crontab에 매일 03:00 캐시 정리 작업이 있지만 이것도 백업이 아닙니다. 이 작업을 새로 추가하거나 실행하지 않았습니다.

```bash
systemctl list-timers --all
sudo crontab -l
ls /etc/cron.d
findmnt /data
df -h /data
```

XFS/ext4 마운트만 확인됐으므로 LVM/ZFS/Btrfs 스냅샷 복구 절차를 현행 기능으로 안내하지 않습니다. 마운트되지 않은 추가 디스크를 백업 디스크로 간주하지 않습니다.

백업을 새로 구성할 때는 별도 저장장치·대상 경로·보존 정책을 정하고 작은 파일로 복원 검증을 합니다. 아래는 **실행 예정 내용을 조회하는 예시**입니다. 실제 원본과 백업 경로로 수정해야 합니다.

```bash
rsync -avn -- /data/PROJECT/ /mnt/VERIFIED_BACKUP/PROJECT/
```

`-n`은 dry-run입니다. 대상 마운트와 원본을 확인하기 전에는 제거하지 않습니다. `--delete`는 기본 예제에 포함하지 않습니다. DB·컨테이너 볼륨은 서비스별 일관성을 보장하는 방법으로 따로 백업합니다.

## 문제를 보고할 때

발생 시각, 실행 명령, 작업번호, 종료 코드, 필요한 범위의 오류 메시지를 함께 전달합니다. 우선 상태·로그를 수집하고 원인이 확인되기 전에 프로세스 종료·재부팅·상태 파일 삭제로 대응하지 않습니다.
