# 서버 매뉴얼

Lab. of Veterinary Informatics and Bioinformatics

College of Veterinary Medicine, Seoul National University

서버 `vbmi`의 **2026-10-24 (Asia/Seoul) 실측 상태**를 기준으로 작성했습니다. 원본 매뉴얼 작성자는 Wongyung Choi이며, 현재 서버에 맞게 개정했습니다.

## 처음 사용하는 경우

1. 관리자에게 서버 주소와 개인 계정을 받습니다.
2. [SSH 접속 및 파일 전송](서버%20매뉴얼/02-SSH-접속-및-파일-전송.md)에 따라 접속합니다.
3. [프로그래밍 환경](서버%20매뉴얼/04-프로그래밍-및-분석-도구.md)에서 실행 파일과 개인 환경을 확인합니다.
4. 긴 분석은 [Slurm 작업 실행](서버%20매뉴얼/05-Slurm-작업-실행.md)을 따라 제출합니다.

`SERVER`는 관리자가 알려 준 주소, `USERNAME`은 발급받은 계정으로 바꿉니다. 별도 표시가 없으면 명령은 서버에서 실행합니다. `sudo` 명령은 관리자용입니다.

| 웹·DB | Nginx, RStudio Server, Shiny Server, MySQL |
| 컨테이너·GUI | Docker + Compose v2, Singularity CE, GDM3 + XRDP |

## 사용 전에 알아둘 제한

- Slurm 밖에서 실행한 분석·컨테이너·웹 서비스는 Slurm 예약량에 포함되지 않습니다. `sinfo`의 `idle`은 서버 전체가 한가하다는 뜻이 아닙니다.
- 현재 Slurm은 메모리를 예약하지만 초과 사용을 강제로 차단하지 않습니다. GPU는 예약 및 `CUDA_VISIBLE_DEVICES` 설정으로 관리하며 장치 접근을 강제 격리하지 않습니다.
- GPU는 1개입니다. 다중 노드·다중 GPU 및 Slurm 회계 DB/QoS 사용 안내는 현행 구성에 포함하지 않습니다.
- 연구 데이터 자동 백업·스냅샷 정책은 이번 확인 범위에서 검증되지 않았습니다. `/data`에 저장했다는 이유만으로 백업된 것으로 간주하지 않습니다.

개인 계정 목록, 키, 비밀번호 및 내부 네트워크 상세는 공개 문서에 기록하지 않습니다. 버전과 용량은 확인 날짜의 상태이며 사용 시 조회 명령으로 다시 확인합니다.
